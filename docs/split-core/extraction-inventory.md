## Candidate seam alternatives (recommendations, not agreed decisions)

A. **Typed enumeration input plus reader callback** (recommended smallest seam): CLI remains owner of persisted index decode/fallback and path selection; pass ordered `{original_id, hidden}` entries + existing filter fields to a pure core listing module. Reader callback retains per-ID native config resolution, RPC and late hidden-index read. Callback error classification distinguishes fatal selection ConfigError from per-record skip; core returns results and structured skipped records for native logging. Core uses existing RegistryInfo facts and preserves address-case/public semantics. Native wrapper still projects CLI shapes and sanitizes core read errors. Benefits: no persisted CLI schema/credentials in shared core, exact lazy order remains expressible, no extra Store access in core registry read. Risk: avoid introducing a new oversized generic public trait solely for one callback; native/WASM external consumers and memory callback make this seam real.

B. **Store reads + serialized config/index inside core**: hides decode/orchestration but forces native JSON schema, config credentials/defaulting and per-access path-error policy into core. Requires a native resolver-aware Store rather than eager mapped PathBufs to preserve timing, or explicitly accepts snapshots. More contract surface and weaker locality for current CLI compatibility. Do not choose merely to demonstrate every Host port is used.

Native Store can be built/tested independently with full methods for explicit mapped NetworkConfig/SecretIndex paths. Selected read wrappers must invoke the existing path selector only when that exact accessor is reached, then construct/use the mapping for that operation. Do not pre-resolve every possible path at command startup. Preserve initial read fallback *outside* generic Store: Store reports real typed permission/I/O errors; CLI decoder retains deliberate default-on-file-error behavior. Wallet/project/cache mappings should not become implicitly available from home guessing.

Define symlink/metadata/remove behavior explicitly before implementation: current reads follow links; secure writers refuse final symlinks. A safe proposed complete adapter preserves read/exists follow semantics, removes only the configured directory entry (does not follow unlink to target), rejects directories as file operations, and uses atomic create_new. The human contract must decide private permission guarantee/error behavior and whether non-private writes preserve normal umask. Never claim a complete mapped Store from read-only tests.

## Refined exact list seam and Store capability profile (parent follow-up)

Prefer the smaller generic functional interface over adding a permanent reader port/error family:

```rust
pub struct ListQuery<'a> {
    pub user_address: &'a str,
    pub filter_user: Option<&'a str>,
    pub all: bool,
    pub expired_only: bool,
    pub active_only: bool,
}
pub fn list_indexed<'a, E>(
    entries: impl IntoIterator<Item = (&'a str, bool)>, // original id, enumeration hidden
    query: ListQuery<'_>,
    mut read: impl FnMut(&str) -> Result<Option<RegistryInfo>, E>,
) -> Result<Vec<(String, RegistryInfo)>, E>;
```

This proposal does not add a sixth Host I/O port: it extracts the iteration/filtering module while each reader callback composes existing Host ports. Native callback invokes current selected reader per entry, preserving per-ID config load and successful-RPC late index load; classifies current ConfigError as Err(native error), logs every other failure immediately using existing warning and returns Ok(None). Core calls reader first, skips None, then runs exact filter sequence. Core errors from read_registry_info remain payload-free through native wrapper. Returning skipped errors in a final aggregate is **not** exact: it defers warnings and can discard earlier warnings when a later fatal error occurs. The generic E avoids making native ConfigError into a shared domain error solely for this transition.

Rows need original ID and all eleven RegistryInfo facts only. Enumeration hidden is an input for filtering. Later index_is_hidden result need not be returned for the selected CLI projection, which hardcodes hidden:false; its **read and any path-selection failure must nevertheless remain** for compatibility. Core comparison preserves case-insensitive address strings and literal recipient `public` behavior; `--user public` must continue to match public records, so never blindly parse filter_user as an Ethereum address. No early filtering before RPC.

Likely exact files for this choice: new `crates/bitbid-core/src/registry_list.rs`; export from core lib.rs; native `blockchain.rs::list_registry_secrets` only switches to new core helper, keeps legacy `list_secrets_with` for hide; selected `blockchain/list_read.rs` may factor a facts-returning internal reader while retaining late index check/error projection. Keep `secrets.rs::list_secrets` formatting projection identical (adapter function maps facts into existing OnChainSecretInfo if needed). Add core public-consumer native/WASM tests, CLI selected-list integration tests, and facade consumer smoke test. Do not migrate stored index schema into core for this pure policy cut.

Alternative with core-owned serialized NetworkConfig/default/load policy is feasible as pure data, but it is **not enough** to preserve dynamic config/RPC selection through existing fixed-endpoint BlockingRpc. Current per-ID config chooses both registry and rpc_url for the same RPC. If core rereads config through Store but Rpc is preconstructed once, changed rpc_url is ignored. A dynamic Rpc adapter that rereads config independently adds another read/selection timing and can mismatch registry and endpoint. Avoid an inter-port mutable handoff or new RpcFactory merely to retain this shape. If the human wants snapshot config semantics, it can simplify this later; that is an explicit behavior choice, not a free extraction. Core would also acquire native config fields containing Pinata secrets unnecessarily for selected listing. Typed enumeration plus existing native reader composition is the bounded compatibility-preserving choice.

Proposed native Store profile using existing enum (new implementation behavior, not a claim about current helper):

- Construction accepts explicitly supplied paths only; no env/home/project precedence or directory creation guessing. NetworkConfig/SecretIndex mapped initially. Other keys all four methods return StoreError::Io with fixed safe `unconfigured store key` text; they never return absence/success. Values/paths/secrets never enter public errors.
- read follows final symlink like current fs::read_to_string; returns exact bytes, missing target→Ok(None); unreadable→PermissionDenied; directory/other errors→Io. exists uses metadata consistent with read: missing/dangling target false, permission error typed, directory Io (configured blobs are files). These are deliberate proposed rules, not pre-existing Store guarantees beyond absence consistency.
- write uses OpenOptions; private=false new files follow OS mode/umask and existing modes retained. private=true creates restricted (Unix 0600 subject to umask, then descriptor permissions if exact 0600 required), enforces privacy via descriptor before data write, and fails typed if enforcement fails. create_new uses atomic create_new, never exists-then-write; existing file/symlink→AlreadyExists. Non-create_new overwrite uses nofollow on Unix, rejects final symlink, truncates only opened target. No wholesale atomic-replace/fsync guarantee introduced. Non-Unix private semantics require explicit documented platform implementation/capability evidence; never silently claim Unix ACL coverage.
- remove uses remove_file/unlink on configured entry; absent success; symlink entry unlinked without following victim target; directory Io; denied PermissionDenied. No recursive removal, parent cleanup, or migration.
- Real OS private/remove/exists/symlink cases must be reviewed independently. The first CLI cutover reads only, so improved tested Store write guarantees do not silently change old wallet/project/index write paths.
