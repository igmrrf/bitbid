bitbid

Hand a secret to one person. Not to a chat log.

bitbid seals a secret to a single recipient's key, keeps the ciphertext on IPFS, and records its expiry, read limit, and revocation on-chain. The plaintext never rests on a server we control, because there is no server.

Signal path

FIG. A · one handoff

A key travels. The secret does not.

The whole handoff is one signal path. Your wallet signs the envelope, the recipient's public key wraps the only key that opens it, and the ciphertext goes somewhere nobody has to trust.

01

Wallet

bitbid init creates a secp256k1 keypair. Created with --password, it is sealed at rest with Argon2id + AES-256-GCM.

02

Shared key

ECDH over secp256k1 between your key and the recipient's, run through HKDF-SHA256, wraps a fresh per-secret key.

03

Payload

The secret is sealed with AES-256-GCM. Only the ciphertext is stored, on IPFS. No plaintext leaves the machine that made it.

04

Lifecycle

expiresAt, maxReads, and revoked are written to the on-chain secret registry against the payload's id.

05

Handoff

The recipient unwraps with their private key and bitbid view. After that the secret is theirs; the chain can stop listing it, but it cannot un-see it.

Plug board

FIG. C · every socket is a command

Every capability is a socket. Patch the ones you need.

CLI-first and scriptable end to end. There is no GUI-only path, and no command that pretends to work.

share

Seal a secret to a recipient with a TTL and a read limit.

bitbid share --content "db-password" --ttl 1h --max-reads 5 --to 0x04…

view

Fetch and unwrap; auto-destructs at the read limit or expiry.

bitbid view <secret_id>

list

Show the secrets you hold, active or expired.

bitbid list --active

revoke

Pull a secret's listing before its expiry.

bitbid revoke <secret_id>

hide

Drop a secret from your own list.

bitbid hide <secret_id>

run

Inject secrets into a process with no plaintext file on disk.

bitbid run -- npm run dev

materialize

Write a tagged secret (pem, json, env) to a real file at 0600.

bitbid materialize <secret_id> --dir ./secrets

convert

Move between .env, JSON, and YAML with prefix, suffix, or embed.

bitbid convert config.json .env.local --format env

validate

Check a .env against .env.schema and generate templates.

bitbid validate -e .env.local -s .env.schema

encrypt

Seal a file at rest; decrypt restores it.

bitbid encrypt .env -o .env.enc

search

Find a pattern inside a file.

bitbid search "API_KEY" --path .env

config

Point at a network: polygon, base, amoy, sepolia, base-sepolia, local.

bitbid config --network amoy

Trust ledger

FIG. D · what is promised

What the chain enforces, and what it only advises.

Cryptography is the promise. Expiry, read limits, and revocation are lifecycle signals, and bitbid says so everywhere it matters.

Cryptographic: not negotiable

  • Confidentiality. Payloads are AES-256-GCM; the per-secret key is wrapped per recipient with ECDH secp256k1 + HKDF-SHA256. Only the recipient key opens it.
  • Key custody. Your private key never leaves your machine. Created with --password, it is sealed at rest with Argon2id + AES-256-GCM.
  • No server in the path. Ciphertext lives on IPFS. There is nothing of ours to breach, because there is nothing of ours.

Best-effort: advisory

  • Expiry, max reads, revocation gate listing and the recorded read count. They do not stop a past recipient from decrypting a payload they already fetched, offline.
  • --to public wraps with a well-known key and provides no confidentiality. For non-sensitive content only.
  • --no-export is a guard rail against accidental file writes, not DRM. A recipient holds the plaintext after decrypt.
  • Materialized files are plaintext on disk at mode 0600. Delete them when you are done.
  • Real backends required. A funded wallet, a deployed registry, and reachable IPFS. With no backend, a clear error, never a fake success.
Install

FIG. E · first run

Start in one line.

Install the CLI, make a wallet, hand off your first secret. Nothing else is required.

Cargo · crates.io 
$ cargo install bitbid
$ bitbid --version
Homebrew · macOS & Linux 
$ brew install igmrrf/tap/bitbid
$ bitbid --help
npm · npx 
$ npx bitbid-cli --help
$ npm install -g bitbid-cli
Binary · GitHub releases 
# grab bitbid-* for your OS from GitHub Releases
$ shasum -a 256 bitbid-*   # verify the checksum
1 · Make a wallet

bitbid init --password: a secp256k1 keypair, sealed at rest.

2 · Seal a secret

bitbid share --content "…" --ttl 1h --to 0x04…: for one recipient.

3 · Run with secrets

bitbid run -- npm run dev: injected into the process, no file.
